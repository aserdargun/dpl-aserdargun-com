# DPL visual specification

Reference: design-concept.png, generated with the built-in Image Gen tool. It is design evidence, not an application asset. Functional HTML/SVG is the application.

Palette: neutral dark #111416, surfaces #191e21, borders #363f43, foreground #edf2f1, muted #aab7bb, lime #c4f277, cyan #81d9e4. No gradients or decorative imagery. Sans-serif system typography, monospace rule IDs; 14px minimum standard controls, 12px secondary metadata. Radius 6–10px, 24px panel padding, 16px gaps.

Primary surface: simple DPL header, three navigation items, language switch. Intro title “Bir karar. Birden fazla yol.”, explanatory line and honest simulation label. Three-column laboratory: six numbered scenarios; code-native decision flow with aligned arrows; policy and readable trace. Evidence below. One primary first-run CTA. Mobile: scenario, conditions, diagram, trace, evidence in that order.

Other required surfaces extend these same tokens: comparison uses three policy columns and explicit common starting conditions; methods uses numbered editorial lessons, source records, ecosystem boundaries. No new imagery required.

Intentional departures from generated illustration: replace invented WHO/health evidence with DPL synthetic sources; use meaningful readable rule IDs; use live event state rather than the mockup's arbitrary active node; add required JSON export and advanced input controls after first run; label historical source updates. Smaller widths reflow diagram nodes while retaining arrows between their boundaries. Necessary UI states and bilingual content follow the user brief.

No user approval gate: user explicitly delegated routine design decisions and requested completed implementation.
